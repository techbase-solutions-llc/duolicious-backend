**Goal:** Give the Ahavah API a real unmatch, so the chat menu's Unmatch, built and held behind `UNMATCH_LIVE` in ahavah-web, can go live and keep its promise: "The match and your conversation are removed for both of you, and you will not see each other in Discover."

**Architecture:** One additive migration (0070) records the pair for good in `unmatched_pair`, adds a hold table `unmatched_message` and widens the two named visibility predicates from migration 0035 (`is_blocked_pair`, `is_deck_suppressed`) to cover an unmatch, so every surface that hides a reported pair hides an unmatched pair in both directions without editing its query. `POST /unmatch/by-uuid/<uuid>` runs in one transaction with both people locked. It records the pair and deletes the `ahavah_match` row, so the chat's match gate and every match reader stop at once. It moves both archives' copies of the conversation out of `mam_message` into the hold. It deletes both inbox rows, both `messaged` rows, the pair's reactions and their deck cache, and skips a match email still in the queue. The likes stay, and the like, super-like, reaction and chat storage paths refuse an unmatched pair. The report email reads the hold; the daily retention cron and both hard deletes empty it. The web flips its switch, wires the call and drops the conversation from each device's cache.

**Tech Stack:** Python 3, Flask, psycopg 3, PostgreSQL, FastAPI chat server, pytest in the `docker-compose.test.yml` api container (ahavah-api); Next.js 16, React 19, Vitest with fake-indexeddb (ahavah-web).

## How a match works today (read on 20 Oct)

- A like is a `liked` row (one per direction). The second like of a pair inserts the `ahavah_match` row in the same statement (`service/decisions` `Q_RECORD_LIKE`, or the super-like in `service/tokens/actions/super_like.py`), both serialised by `lock_like_members` (both person rows `FOR UPDATE` in id order).
- `skipped` holds two things told apart by `reported`: a pass (hides the person from the passer's deck for 30 days, migration 0059) and a report (hides the pair from each other on every surface, for good). `POST /skip/by-uuid/<uuid>` without a reason is a pass; with one it is a report, which also emails the moderation inbox with the reporter's last 25 messages with that person (`antiabuse/lodgereport`). Every surface asks the named predicates from migration 0035: `is_blocked_pair` (profile, Views, map, likes tabs, matches, chat gate, presence, the like and message emails, quick questions, referrals) and `is_deck_suppressed` (Discover). The blocked list (`GET /blocked`) and the report figures read `skipped.reported` directly.
- Chat (`service/chat`, a separate FastAPI container) refuses a message unless an `ahavah_match` row exists, then refuses it again if `is_blocked_pair`; both checks are cached 5 seconds per worker. A message is stored twice in `mam_message` (the sender's 'O' copy and the recipient's 'I' copy, `person_id` the archive's owner, `remote_bare_jid` the other uuid), once in each person's `inbox` row (`luser` uuid, `remote_bare_jid` uuid@domain, no key to person) and as a `messaged` row on a first message. The web's Inbox is the XMPP inbox query over `inbox`; a thread's history is the MAM query over `mam_message`; each device also keeps its last 50 messages per thread in IndexedDB (`ahavah-web/src/lib/chat-cache.ts`).
- Account deletion is soft for 7 days (`activated = FALSE`; every surface drops the person), then hard (`service/cron/pendingdeletion` and `DELETE /admin/users/<uuid>`): the person row goes and `mam_message` (the deleter's copies), `ahavah_match`, `liked`, `skipped`, `messaged`, reactions and outbox rows cascade; `inbox` and voice files are cleaned by hand (`service/hard_delete.py`). The other person keeps their own copies of the conversation today.

## Decisions taken

Defaults so the work can start. The owner may change any of them; each is repeated under "Spec conflicts and decisions needing the owner".

1. **Removed, not erased at once.** Both copies of every message leave `mam_message`, the inbox and the data export at the moment of the unmatch. They are held, out of every member surface, for 30 days in `unmatched_message`, for one use only: if either person reports the other, the report email carries them as it does today. The daily retention cron deletes them at the end of the hold, and either person's hard delete takes both sides sooner. Voice notes go to the CDN cleaner's queue at the same time.
2. **Permanent and mutual.** `unmatched_pair` keeps the pair for as long as both accounts exist. Neither person can see, like, super-like, react to or message the other again; there is no undo.
3. **Hidden everywhere a report hides, not only in Discover.** Profile, Views, map, likes tabs, matches, chat, presence and the member emails. The blocked list does not show an unmatched person (an unmatch is not a report), and unblocking a report never undoes an unmatch.
4. **Reporting still works.** `POST /skip/by-uuid/<uuid>` with a reason works after an unmatch, from either side; the report reaches the moderation inbox with the held messages.
5. **The likes stay.** They are what happened, they keep the Overview's engagement figures true and, with the pair record, cannot make a match again.
6. **The other person is not told.** No push, email or line. Their conversation disappears; an open chat refuses their next message with the existing "Not sent. You can only message people you are matched with".
7. **Counts.** Growth's Matches and Matches 30d keep counting a match that was made and then ended (`unmatched_pair.matched_at`). Message figures (Growth's messages 7d and 30d, the Overview's messages and conversations) drop the unmatched conversation at once, because they count `mam_message`. The Overview's Matches (mutual likes) does not move. No Unmatches figure is built.
8. **Push and email.** A match email still queued for the match is skipped. Match and message reminders, the unread-message email, quick question pushes about the match and the weekly emails stop by themselves (they read `ahavah_match`, `inbox` or `is_blocked_pair`). A message sent within the chat gate's 5 second cache of the unmatch may still show live on an open screen and send its push, but is never stored.
9. **Together and quick questions.** Nothing in Together is removed: an Us game started from the chat stays the member's own. The match's quick question goes with the match row (`match_question` cascades); each person's own answers stay.

```python
"""Set-up the unmatch tests share (TEC-1845, migration 0070): a matched pair
and a conversation stored the way the app stores them, and a count of what
is left of it."""
from __future__ import annotations

import itertools
import time

from database import api_tx

# The chat server's LSERVER default (service/chat/chatutil). The inbox stores
# the other person as uuid@domain; the archive stores the bare uuid.
DOMAIN = 'ahavah.app'
_seq = itertools.count()


def match(a: dict, b: dict) -> str:
    """Both likes and the match row, as /decisions leaves them."""
    with api_tx() as tx:
        for liker, liked in ((a, b), (b, a)):
            tx.execute(
                "INSERT INTO liked (liker_id, liked_id) VALUES (%(a)s, %(b)s) ON CONFLICT DO NOTHING",
                dict(a=liker['id'], b=liked['id']))
        return tx.execute(
            """INSERT INTO ahavah_match (user_a_id, user_b_id)
               VALUES (LEAST(%(a)s, %(b)s), GREATEST(%(a)s, %(b)s))
               RETURNING match_id::text AS match_id""",
            dict(a=a['id'], b=b['id'])).fetchone()['match_id']


def converse(sender: dict, recipient: dict, body: str = 'Shalom',
             audio_uuid: str | None = None) -> int:
    """One message as service/chat/messagestorage stores it: a copy in each
    archive ('O' for the sender, 'I' for the recipient), both inbox rows and
    the sender's messaged row. Returns the sender's archive id."""
    mid = ((time.time_ns() // 1000) << 8) + 2 * next(_seq)
    with api_tx() as tx:
        tx.execute(
            """INSERT INTO mam_message (id, from_jid, remote_bare_jid, direction, message,
                                        search_body, audio_uuid, person_id)
               VALUES (%(id)s, '', %(to)s, 'O', %(m)s, %(b)s, %(au)s, %(sid)s),
                      (%(id)s + 1, '', %(frm)s, 'I', %(m)s, %(b)s, %(au)s, %(rid)s)""",
            dict(id=mid, to=recipient['uuid'], frm=sender['uuid'], m=body.encode(),
                 b=body.lower(), au=audio_uuid, sid=sender['id'], rid=recipient['id']))
        for luser, remote, unread in ((sender, recipient, 0), (recipient, sender, 1)):
            tx.execute(
                """INSERT INTO inbox (luser, remote_bare_jid, msg_id, box, content, timestamp,
                                      unread_count)
                   VALUES (%(l)s, %(r)s, %(mid)s, 'chats', %(c)s, %(ts)s, %(n)s)
                   ON CONFLICT (luser, remote_bare_jid) DO UPDATE
                      SET unread_count = EXCLUDED.unread_count""",
                dict(l=luser['uuid'], r=f"{remote['uuid']}@{DOMAIN}", mid=str(mid),
                     c=b'<message/>', ts=mid >> 8, n=unread))
        tx.execute(
            """INSERT INTO messaged (subject_person_id, object_person_id)
               VALUES (%(s)s, %(o)s) ON CONFLICT DO NOTHING""",
            dict(s=sender['id'], o=recipient['id']))
    return mid


def counts(a: dict, b: dict) -> dict:
    """What is left of this pair's match and conversation, where each is kept."""
    with api_tx('read committed') as tx:
        return dict(tx.execute(
            """SELECT
                 (SELECT count(*) FROM mam_message
                   WHERE (person_id = %(a)s AND split_part(remote_bare_jid, '@', 1) = %(bu)s)
                      OR (person_id = %(b)s AND split_part(remote_bare_jid, '@', 1) = %(au)s)) AS archive,
                 (SELECT count(*) FROM unmatched_message
                   WHERE (person_id = %(a)s AND split_part(remote_bare_jid, '@', 1) = %(bu)s)
                      OR (person_id = %(b)s AND split_part(remote_bare_jid, '@', 1) = %(au)s)) AS held,
                 (SELECT count(*) FROM inbox
                   WHERE (luser = %(au)s AND split_part(remote_bare_jid, '@', 1) = %(bu)s)
                      OR (luser = %(bu)s AND split_part(remote_bare_jid, '@', 1) = %(au)s)) AS inbox,
                 (SELECT count(*) FROM messaged
                   WHERE (subject_person_id = %(a)s AND object_person_id = %(b)s)
                      OR (subject_person_id = %(b)s AND object_person_id = %(a)s)) AS messaged,
                 (SELECT count(*) FROM ahavah_match
                   WHERE user_a_id = LEAST(%(a)s, %(b)s)
                     AND user_b_id = GREATEST(%(a)s, %(b)s)) AS matches""",
            dict(a=a['id'], b=b['id'], au=a['uuid'], bu=b['uuid'])).fetchone())
```

```python
"""Migration 0070 (TEC-1845): unmatch. An unmatched pair is a barrier both
ways, in every predicate a surface asks; a report and a pass keep their own
rules. The deploy may run the file more than once, so every test runs it
twice first."""
from __future__ import annotations

from pathlib import Path

import psycopg
import pytest

from database import api_tx

_MIGRATION = Path(__file__).resolve().parent.parent / 'migrations' / '0070_unmatch.sql'


def _apply() -> None:
    with api_tx() as tx:
        tx.execute(_MIGRATION.read_text(encoding='utf-8'))


@pytest.fixture(autouse=True)
def _applied_twice():
    _apply()
    _apply()


def _unmatched(tx, a: dict, b: dict, by: dict) -> None:
    tx.execute(
        """INSERT INTO unmatched_pair (user_a_id, user_b_id, unmatched_by)
           VALUES (LEAST(%(a)s, %(b)s), GREATEST(%(a)s, %(b)s), %(by)s)""",
        dict(a=a['id'], b=b['id'], by=by['id']))


def _ask(tx, fn: str, x: dict, y: dict) -> bool:
    return tx.execute(f'SELECT {fn}(%(x)s, %(y)s) AS v', dict(x=x['id'], y=y['id'])).fetchone()['v']


def test_an_unmatch_is_a_barrier_both_ways(unmatch_pair):
    a, b = unmatch_pair.a, unmatch_pair.b
    with api_tx() as tx:
        assert not _ask(tx, 'is_blocked_pair', a, b)
        _unmatched(tx, a, b, a)
        for fn in ('is_unmatched_pair', 'is_blocked_pair', 'is_deck_suppressed'):
            assert _ask(tx, fn, a, b), fn
            assert _ask(tx, fn, b, a), fn


def test_a_pass_and_a_report_keep_their_rules(unmatch_pair):
    a, b = unmatch_pair.a, unmatch_pair.b
    with api_tx() as tx:
        tx.execute(
            """INSERT INTO skipped (subject_person_id, object_person_id, reported)
               VALUES (%(a)s, %(b)s, FALSE)""", dict(a=a['id'], b=b['id']))
        assert not _ask(tx, 'is_blocked_pair', a, b)
        assert _ask(tx, 'is_deck_suppressed', a, b)
        assert not _ask(tx, 'is_deck_suppressed', b, a), 'a pass is one-directional (0036)'
        tx.execute(
            """UPDATE skipped SET reported = TRUE
                WHERE subject_person_id = %(a)s AND object_person_id = %(b)s""",
            dict(a=a['id'], b=b['id']))
        assert _ask(tx, 'is_blocked_pair', b, a)
        assert _ask(tx, 'is_deck_suppressed', b, a)


def test_the_pair_is_stored_once_lower_id_first(unmatch_pair):
    a, b = unmatch_pair.a, unmatch_pair.b
    lo, hi = sorted((a['id'], b['id']))
    with pytest.raises(psycopg.errors.CheckViolation):
        with api_tx() as tx:
            tx.execute(
                """INSERT INTO unmatched_pair (user_a_id, user_b_id, unmatched_by)
                   VALUES (%(hi)s, %(lo)s, %(hi)s)""", dict(lo=lo, hi=hi))
    with pytest.raises(psycopg.errors.UniqueViolation):
        with api_tx() as tx:
            _unmatched(tx, a, b, a)
            _unmatched(tx, b, a, b)


def test_only_one_of_the_two_can_have_unmatched(unmatch_pair, make_person):

    leaving, staying = make_person(name='Leaving'), make_person(name='Staying')
    with api_tx() as tx:
        _unmatched(tx, leaving, staying, leaving)
```

```sql
-- 0070_unmatch.sql
-- Unmatch (TEC-1845). The chat menu's Unmatch promises, in the design's
-- words (ahavah-web Claude Design/handoff/copy/15-together-follow-ups.md,
-- 6.2): "The match and your conversation are removed for both of you, and
-- you will not see each other in Discover."
--
-- Additive. The deploy applies each file once and records its checksum
-- (scripts/apply-deploy-migrations.sh), and stops if an applied file
-- changes: never edit this file once it has shipped; a change is the next
-- number. Idempotent, because the test fixtures apply it at every session
-- start.

-- 1. The pair, for good. One row per pair, the lower person id first, as in
-- ahavah_match. matched_at keeps when the match was made, so Growth still
-- counts a match that happened. The row goes with either person's account.
CREATE TABLE IF NOT EXISTS unmatched_pair (
  user_a_id     INT         NOT NULL REFERENCES person(id) ON DELETE CASCADE,
  user_b_id     INT         NOT NULL REFERENCES person(id) ON DELETE CASCADE,
  unmatched_by  INT         NOT NULL,
  matched_at    TIMESTAMPTZ,
  unmatched_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (user_a_id, user_b_id),
  CHECK (user_a_id < user_b_id),
  CHECK (unmatched_by IN (user_a_id, user_b_id))
);

CREATE INDEX IF NOT EXISTS idx__unmatched_pair__user_b ON unmatched_pair (user_b_id);

-- 2. The conversation, out of sight. Both archives' copies move here from
-- mam_message in the unmatch's own transaction, so no member surface, chat
-- history or data export can show them. They are read only by the report
-- email (antiabuse/sql Q_LAST_MESSAGES) and deleted at held_until by the
-- daily retention cron (service/cron/leadretention), or with either
-- person's account. Translations are not kept.
CREATE TABLE IF NOT EXISTS unmatched_message (
  person_id        INT           NOT NULL REFERENCES person(id) ON DELETE CASCADE,
  id               BIGINT        NOT NULL,
  remote_bare_jid  VARCHAR(250)  NOT NULL,
  direction        mam_direction NOT NULL,
  message          BYTEA         NOT NULL,
  search_body      TEXT,
  audio_uuid       TEXT,
  held_until       TIMESTAMPTZ   NOT NULL,
  PRIMARY KEY (person_id, id)
);

CREATE INDEX IF NOT EXISTS idx__unmatched_message__held_until
  ON unmatched_message (held_until);

-- 3. The named predicate (the 0035 pattern: a caller picks a meaning by
-- name instead of hand-rolling a clause and forgetting one).
CREATE OR REPLACE FUNCTION is_unmatched_pair(a INT, b INT)
RETURNS BOOLEAN
LANGUAGE sql
STABLE
AS $$
    SELECT EXISTS (
        SELECT 1
        FROM unmatched_pair
        WHERE user_a_id = LEAST(a, b)
          AND user_b_id = GREATEST(a, b)
    );
$$;

-- 4. The hard barrier now has two causes: a report either way (0035), or an
-- unmatch. Every surface that hides a reported pair hides an unmatched pair,
-- in both directions: profile, Views, map, likes, matches, chat, presence and
-- the member emails. The blocked list and report counts read
-- skipped.reported directly and are not touched.
CREATE OR REPLACE FUNCTION is_blocked_pair(a INT, b INT)
RETURNS BOOLEAN
LANGUAGE sql
STABLE
AS $$
    SELECT EXISTS (
        SELECT 1
        FROM skipped
        WHERE reported
          AND (
                (subject_person_id = a AND object_person_id = b)
             OR (subject_person_id = b AND object_person_id = a)
          )
    )
    OR is_unmatched_pair(a, b);
$$;

-- 5. Discover. The 0059 body, plus an unmatch, both ways and for good.
CREATE OR REPLACE FUNCTION is_deck_suppressed(searcher INT, prospect INT)
RETURNS BOOLEAN
LANGUAGE sql
STABLE
AS $$
    SELECT EXISTS (
        SELECT 1
        FROM skipped
        WHERE (
                -- The searcher's own pass or report.
                subject_person_id = searcher
                AND object_person_id = prospect
                AND (reported OR created_at > NOW() - INTERVAL '30 days')
          )
          OR (
                -- The prospect's action only counts when it is a report.
                subject_person_id = prospect
                AND object_person_id = searcher
                AND reported
          )
    )
    OR is_unmatched_pair(searcher, prospect);
$$;
```

Create `service/decisions/unmatch.py`:

```python
"""Unmatch (TEC-1845; ahavah-web Claude Design/handoff/copy/
15-together-follow-ups.md, section 6).

6.2 promises: "The match and your conversation are removed for both of you,
and you will not see each other in Discover." One transaction, both people
locked in the like order (service/decisions/locking.py), so a like or a
super-like racing it either lands first and is undone here, or waits and
then meets the pair record:

  - unmatched_pair records the pair for good (migration 0070).
    is_blocked_pair covers it, so every surface a report hides the pair
    from hides an unmatched pair too, both ways; is_deck_suppressed covers
    it for Discover.
  - the ahavah_match row goes (match_question cascades), so the chat's
    match gate and every match reader stop at once.
  - both archives' copies of the conversation move from mam_message to
    unmatched_message: out of chat history, the inbox and the data export,
    held HOLD_DAYS for a report (antiabuse/sql Q_LAST_MESSAGES), then
    deleted by purge_held_messages (the daily leadretention cron).
  - both inbox rows, both messaged rows, the pair's reactions and their
    deck cache go, and a match email still queued for this match is skipped.

The likes stay. They are what happened and they keep the engagement figures
true; with unmatched_pair they cannot make a match again (Q_RECORD_LIKE and
the super-like refuse an unmatched pair).

Repeating it from either side answers as a success: the web's Try again
after a lost response must not read as a failure. Nobody is notified.
"""
from __future__ import annotations

from typing import Union

import duotypes as t
from database import api_tx
from service.decisions.locking import lock_like_members

HOLD_DAYS = 30

_Q_PAIR = """
    SELECT peer.id AS peer_id, peer.uuid::text AS peer_uuid, me.uuid::text AS me_uuid,
           m.match_id::text AS match_id, m.created_at AS matched_at,
           is_unmatched_pair(me.id, peer.id) AS unmatched
      FROM person me
      JOIN person peer
        ON peer.uuid = uuid_or_null(%(peer_uuid)s::text)
       AND peer.id <> me.id
      LEFT JOIN ahavah_match m
        ON m.user_a_id = LEAST(me.id, peer.id)
       AND m.user_b_id = GREATEST(me.id, peer.id)
     WHERE me.id = %(me)s
"""

_Q_RECORD = """
    INSERT INTO unmatched_pair (user_a_id, user_b_id, unmatched_by, matched_at)
    VALUES (LEAST(%(me)s, %(peer)s), GREATEST(%(me)s, %(peer)s), %(me)s, %(matched_at)s)
    ON CONFLICT (user_a_id, user_b_id) DO NOTHING
"""

_Q_END_MATCH = """
    DELETE FROM ahavah_match WHERE match_id = %(match_id)s::uuid
"""

# The archive stores the other person as a bare uuid and the inbox as
# uuid@domain; split_part reads both.
_Q_HOLD_MESSAGES = """
    WITH moved AS (
        DELETE FROM mam_message m
         WHERE (m.person_id = %(me)s   AND split_part(m.remote_bare_jid, '@', 1) = %(peer_uuid)s)
            OR (m.person_id = %(peer)s AND split_part(m.remote_bare_jid, '@', 1) = %(me_uuid)s)
        RETURNING m.person_id, m.id, m.remote_bare_jid, m.direction, m.message,
                  m.search_body, m.audio_uuid
    )
    INSERT INTO unmatched_message (person_id, id, remote_bare_jid, direction, message,
                                   search_body, audio_uuid, held_until)
    SELECT person_id, id, remote_bare_jid, direction, message, search_body, audio_uuid,
           NOW() + make_interval(days => %(days)s)
      FROM moved
    ON CONFLICT (person_id, id) DO NOTHING
"""

_Q_FORGET_INBOX = """
    DELETE FROM inbox
     WHERE (luser = %(me_uuid)s   AND split_part(remote_bare_jid, '@', 1) = %(peer_uuid)s)
        OR (luser = %(peer_uuid)s AND split_part(remote_bare_jid, '@', 1) = %(me_uuid)s)
"""

_Q_FORGET_MESSAGED = """
    DELETE FROM messaged
     WHERE (subject_person_id = %(me)s   AND object_person_id = %(peer)s)
        OR (subject_person_id = %(peer)s AND object_person_id = %(me)s)
"""

_Q_FORGET_REACTIONS = """
    DELETE FROM message_reactions
     WHERE (reactor_id = %(me)s   AND peer_id = %(peer)s)
        OR (reactor_id = %(peer)s AND peer_id = %(me)s)
"""

_Q_FORGET_DECK = """
    DELETE FROM search_cache
     WHERE (searcher_person_id = %(me)s   AND prospect_person_id = %(peer)s)
        OR (searcher_person_id = %(peer)s AND prospect_person_id = %(me)s)
"""

# The "It's a match!" email is queued under match-<match id>
# (service/decisions post_decisions). Queued only: one already reserved is
# on its way.
_Q_SKIP_MATCH_EMAIL = """
    UPDATE email_outbox SET state = 'skipped', last_error = 'unmatched'
     WHERE campaign = 'match' AND campaign_id = 'match-' || %(match_id)s
       AND state = 'queued'
"""

_STATEMENTS = (_Q_RECORD, _Q_END_MATCH, _Q_HOLD_MESSAGES, _Q_FORGET_INBOX,
               _Q_FORGET_MESSAGED, _Q_FORGET_REACTIONS, _Q_FORGET_DECK, _Q_SKIP_MATCH_EMAIL)

_Q_UNMATCHED = """
    SELECT p.uuid::text AS uuid
      FROM unmatched_pair u
      JOIN person p
        ON p.id = CASE WHEN u.user_a_id = %(me)s THEN u.user_b_id ELSE u.user_a_id END
     WHERE u.user_a_id = %(me)s OR u.user_b_id = %(me)s
     ORDER BY u.unmatched_at DESC
"""

# A voice note is one file both copies name. It goes to the CDN cleaner's
# queue unless a live message still names it.
_Q_PURGE_HELD = """
    WITH gone AS (
        DELETE FROM unmatched_message
         WHERE held_until < NOW()
        RETURNING audio_uuid
    ), staged AS (
        INSERT INTO undeleted_audio (uuid)
        SELECT DISTINCT g.audio_uuid
          FROM gone g
         WHERE g.audio_uuid IS NOT NULL
           AND NOT EXISTS (SELECT 1 FROM mam_message m WHERE m.audio_uuid = g.audio_uuid)
        ON CONFLICT DO NOTHING
    )
    SELECT 1 FROM gone
"""


def unmatch(s: t.SessionInfo, prospect_uuid: str) -> Union[dict, tuple]:
    if s.person_id is None:
        return 'Not signed in', 401

    with api_tx('READ COMMITTED') as tx:
        lock_like_members(tx, s.person_id, prospect_uuid)
        pair = tx.execute(_Q_PAIR, dict(me=s.person_id, peer_uuid=prospect_uuid)).fetchone()
        if pair is None or (pair['match_id'] is None and not pair['unmatched']):
            return {'error': 'not_matched'}, 404
        if pair['match_id'] is None:
            return {'ok': True}
        params = dict(
            me=s.person_id, peer=pair['peer_id'],
            me_uuid=pair['me_uuid'], peer_uuid=pair['peer_uuid'],
            match_id=pair['match_id'], matched_at=pair['matched_at'],
            days=HOLD_DAYS,
        )
        for statement in _STATEMENTS:
            tx.execute(statement, params)

    return {'ok': True}


def unmatched_people(s: t.SessionInfo) -> dict:
    """Everyone the caller is unmatched from, whoever unmatched. The web drops
    those conversations from the device's own cache (src/lib/unmatch.ts)."""
    with api_tx('READ COMMITTED') as tx:
        rows = tx.execute(_Q_UNMATCHED, dict(me=s.person_id)).fetchall()
    return {'uuids': [r['uuid'] for r in rows]}


def purge_held_messages(tx) -> int:
    """Delete every held message whose hold has ended. Daily, from
    service/cron/leadretention. Returns how many rows went."""
    return tx.execute(_Q_PURGE_HELD).rowcount
```

```ts
export async function clearThread(owner: string, threadId: string): Promise<void> {
  if (!owner || !threadId || typeof indexedDB === "undefined") return;
  try {
    const db = await openDB();
    await new Promise<void>((resolve, reject) => {
      const tx = db.transaction(STORE, "readwrite");
      const store = tx.objectStore(STORE);
      const req = store.index(THREAD_INDEX).getAllKeys([owner, threadId]);
      req.onsuccess = () => { for (const key of req.result) store.delete(key); };
      tx.oncomplete = () => resolve();
      tx.onerror = tx.onabort = () => reject(tx.error);
    });
  } catch { /* The server copy is gone either way; the next open tries again. */ }
}
```

```ts
/**
 * Unmatch from the chat (TEC-1845; follow-ups export section 6).
 *
 * POST /unmatch/by-uuid/{uuid} (ahavah-api service/decisions/unmatch.py,
 * migration 0070) ends the match and removes the conversation for both
 * people, as 6.2 promises: "The match and your conversation are removed for
 * both of you, and you will not see each other in Discover." Repeating it,
 * or calling it after the other person unmatched, answers as a success, so
 * 6.4's Try again after a lost response lands on 6.5.
 *
 * The server keeps nothing either person can open, but each device keeps
 * its own recent history (src/lib/chat-cache.ts). The member who unmatches
 * drops it at once; the other person's device drops it the next time the
 * Inbox or that chat opens, from GET /unmatched.
 */
import { apiClient } from "@/lib/api-client";
import { clearThread } from "@/lib/chat-cache";

export const UNMATCH_LIVE = true;

/** The call the sheet makes. Rejects unless the API answers 2xx. */
export async function unmatch(prospectUuid: string): Promise<void> {
  await apiClient.post(`/unmatch/by-uuid/${encodeURIComponent(prospectUuid)}`, {});
}

/**
 * Drops this device's copy of every conversation an unmatch removed, by
 * either person, and says whose. Never rejects: when the list cannot be
 * read the cache stays as it was and the next open tries again.
 */
export async function forgetUnmatched(myUuid: string): Promise<ReadonlySet<string>> {
  if (!myUuid) return new Set();
  try {
    const res = await apiClient.get<{ uuids?: unknown }>("/unmatched");
    const uuids = Array.isArray(res.uuids)
      ? res.uuids.filter((u): u is string => typeof u === "string")
      : [];
    await Promise.all(uuids.map((u) => clearThread(myUuid, u)));
    return new Set(uuids);
  } catch {
    return new Set();
  }
}

/** The Inbox address after an unmatch; the Inbox shows 6.5's toast for it. */
export const UNMATCHED_INBOX = "/inbox?unmatched=1";
```

## Spec conflicts and decisions needing the owner

Each item says what the design asks, what the data model can honestly give, what this plan does by default and what it needs from the owner.

1. **How long the removed conversation is kept, and the privacy line.** The design says the conversation is "removed for both of you". The plan removes it at once from every member surface, the chat history and the data export, and holds it out of sight for 30 days for one use: a report made after the unmatch, whose email to the moderation inbox already carries the last 25 messages. It is then deleted, and either account's hard delete takes it sooner. The privacy page (`ahavah-web/src/app/legal/privacy/page.tsx`) says nothing about keeping messages. Choose the hold (0 days, so a later report carries no messages; 30, the default; or another number), and approve a privacy line in this sense, to be drafted and run through `/copy-pass`: when you unmatch, the conversation is removed for both of you at once, and we keep a hidden copy for 30 days only so a report can still be checked, then delete it.
2. **Reporting someone you unmatched.** The API accepts the report from either person after an unmatch (Task 5). The web gives no way to reach the person afterwards: the chat and the profile are gone for both, and the design has no list of people you unmatched. Today a member can report from the same menu before unmatching, or write to support. Decide whether that is enough, or whether a "People you unmatched" list beside Blocked in Settings, with Report, should go to Claude Design as a brief into the existing project.
3. **Permanent, with no way back.** The plan reads "you will not see each other in Discover" as for good: no undo, and no like, super-like or reaction can make the pair a match again. Decide whether an undo (by the member, or by support) is ever wanted.
4. **Hidden beyond Discover.** The design promises Discover only. The plan hides the pair from each other everywhere a report does: profile, Views, map, likes tabs, matches, chat, presence and the member emails, because a member who unmatched someone would not expect to meet them on the map or in Views. Confirm, or name the surfaces that should still show them.
5. **The other person is not told.** The design draws only the side of the member who unmatches. The plan sends the other person no push, email or line: their conversation disappears, and an open chat refuses their next message with the existing "Not sent. You can only message people you are matched with". Decide whether they should be told, which would need a design and its copy.
6. **What happens to the counts.** Growth's Matches and Matches 30d keep counting a match that was made and then ended (Task 7); the Overview's Matches (mutual likes) does not move, since the likes stay. Message figures (Growth's messages 7d and 30d, the Overview's messages, conversations and conversations answered) drop the unmatched conversation's messages at once, because they count only the live archive. No Unmatches figure is built: the admin design has no tile for it, and it would be counts only. Decide whether messages should keep counting through the hold, and whether an Unmatches count should be designed.
7. **The data export.** Held messages are not in a member's data export, since the conversation is removed. During the hold a copy exists that staff could produce from the database on a legal request. Confirm.
8. **Push and email in the moment of the unmatch.** A match email still queued for the match is skipped, and every later reminder stops. The chat gate caches "matched" for 5 seconds per chat worker, so a message sent within that window of the unmatch may still appear on the other person's open screen and send its push, though it is never stored (Task 4). Accept, or remove the cache at the cost of one more database read per message.
9. **Together.** The API keeps no link between a Together session and a match, so an unmatch removes nothing in Together. An Us game started from the chat ("Play Us together") stays the member's own; a game both people played keeps its shared result for each of them. When the game finishes it returns to the chat, which now sends the member to the Inbox, so the invite it would have put in the message box is not offered. Decide whether an unmatch should also delete an Us game or couple checklist both of them joined (the API can find one by the person id on both seats).
10. **Quick questions.** The match's quick question goes with the match row (`match_question` cascades); each person's own answers stay on their profile, where the other can no longer see them. No decision needed unless you want them handled differently.
11. **Staff accounts.** Staff accounts unmatch and are unmatched like members and stay out of every count as now. There is no admin view of who unmatched whom. Confirm that support should not see a list of unmatches.
12. **The likes stay.** The plan keeps both `liked` rows: they record what happened, keep the Overview's figures true and, with the pair record, cannot make a match again. The alternative is deleting them, which would drop the Overview's Matches and leave the pair record as the only guard. Confirm.
13. **No new lines.** The web shows no line when the other person's device drops a removed conversation or when an old chat link sends them to the Inbox. If a line is wanted there, it needs a frame from Claude Design and a `/copy-pass` (ux-writing) pass.
14. **Found while reading, not changed.** `POST /tokens/rewind` (`service/tokens/actions/rewind.py`) deletes the caller's `skipped` row for a person whether or not it is a report, so 1 token undoes a block, against migration 0035's rule that a report is permanent. It does not touch an unmatch (that lives in `unmatched_pair`). Say whether it should be fixed in its own issue.
